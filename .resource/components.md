## Key architectural notes

- **Entity IDs:** all entities use `guid` (UUID v4). Items always did; Loadouts and Recipes migrated from short `id` strings in Dexie schema v2.
- **DATA singleton:** `store.js` exports a mutable `DATA` object updated by `loadData()`. Screens read it directly (no React state for the list). Always call `await loadData()` after any write before touching `DATA`.
- **ContextMenu pattern:** wrap `SidebarItem` with `<ContextMenuTrigger asChild>` directly. Put `<Tooltip>` *inside* the SidebarItem around the content div — never between `ContextMenu` and `ContextMenuTrigger`, or the browser native menu shows instead.
- **Taxonomy:** categories, rarities, attachment slots, crafting stations, item actions all live in `useTaxonomy()`. Screens call `const [tax] = useTaxonomy()` and pass `taxonomy` to `FormRenderer`.
- **i18n:** `useTranslation()` → `t('section.key')`. Interpolation: `t('common.deleteConfirmDesc', { name })`.
